# Portfolio visual reference system

This folder is the source of truth for matching the approved visual concepts. The seven reference images were supplied in this conversation on 17 November 2026. They are catalogued below by their uploaded filenames and exact pixel dimensions.

## Direction
A bright, uplifting, high-detail fantasy-tech universe. It is not a dark developer portfolio and must not collapse into a conventional stack of cards on a plain background.

- Atmosphere: luminous sky, soft clouds, floating islands, distant mountains, waterfalls, gardens, cherry blossoms and warm sunlight.
- Core composition: a personalized Yash character, a small friendly robot companion, a glowing YP portal and floating project / discipline environments.
- UI: translucent glass surfaces, rounded capsule navigation, glowing violet CTAs, thin white borders, soft shadows and carefully controlled neon accents.
- Narrative: visitors travel through a connected creative universe; projects and disciplines feel like destinations, not a generic list of cards.

The concepts contain AI-generated lettering and UI details. Rebuild all live text as real HTML, not baked-in text from the image. Use real project screenshots / authored 3D models for final fidelity.

## Non-negotiable implementation rules
- Keep the light, colorful, optimistic mood. No dark default theme.
- Do not replace the main 3D world with emoji, generic gradients, or flat CSS cards.
- Build responsive compositions intentionally for desktop, tablet and mobile; never shrink a desktop screenshot into a phone.
- Keep text, navigation, cards, controls and CTAs as accessible DOM elements.
- Use real 3D assets / GLB models for the hero character, robot, portal, islands and environment where practical.
- Keep every model, texture, font, icon and image documented in the asset inventory.
- Respect reduced-motion preferences and provide a non-WebGL fallback.
- Treat numeric values and project claims in mockups as visual placeholders until verified.
